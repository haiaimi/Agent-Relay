# 游戏团队工作室

新电脑准备资产制作环境，见 [资产管线与换机指南](asset-pipeline.md)：自动下载 Blender、锁定 Python 依赖，制作源模型、GLB、预览和本机视频，再接入团队共享工具设置及项目正式管线。

入口：网站的 **游戏团队工作室**，或直接访问 `/studio`。沿用 Relay 的访问密钥，支持手机、桌面浏览器，独立桌面版启动后直接显示团队工作台；桌面快捷方式为「Agent Relay 游戏工作室」，上方「工作台」菜单可切换会话或打开 Agent 与模型设置。

侧边栏随工作区切换：会话工作台显示最近会话，游戏工作室显示当前团队的需求完成进度、待处理事项和各职能任务。点击需求查看整体详情，展开职能进度后可直接打开任务；侧边栏和主画面的团队选择保持同步。手机通过同一个滑动侧边栏操作，页面保持固定。

会话工作台、职能对话、团队群聊与头脑风暴使用浏览器本地缓存。切换时先显示已读记录并恢复阅读位置，再后台同步；重新打开网页后也会读取本设备缓存。已加载的更早历史保留分页位置，图片沿用已有设备缓存。缓存按最近使用回收，浏览器拒绝持久存储时仍可在当前页面内缓存；退出登录或认证失效会清理。缓存仅用于展示，不会重发消息或审批；待回答问题需同步后才能提交。

## 使用流程

PC 网页的会话工作台、职能对话、团队群聊和头脑风暴统一支持 Enter 发送、Shift+Enter 换行。中文输入法选词确认不会触发发送；手机的工作室回复框保留回车换行。键盘发送与点击发送按钮使用同一附件、校验和防重复提交逻辑。

需求显示“已交付”后，职能对话和群聊仍可追问。向已完成任务发送消息会开启独立的“交付后讨论”，带上流程、原任务及交付摘要；后续消息继续该讨论。它使用原需求工作副本，默认只读讨论；明确要求的本机启动可按试玩约定运行已有成果，仍沿用工具审批，不重开生产、不改变源码、任务和批准记录。需要继续制作时，在需求详情选择“基于本次交付继续制作”；取消的需求和历史执行记录仍不可直接发送。会话启动结果不明时先核对、绑定或确认未启动，不自动重发。

职能对话输入框上方提供“执行权限”：请求批准、帮我批准、完全访问。选择会更新当前所选会话，并保存为本需求中该职能新对话的默认值；其他会话、其他职能和团队生产权限不跟着改变。新对话未单独设置时沿用团队权限，交付后对话也不再强制降为请求批准。完全访问允许 Agent 访问本机文件和网络、跳过常规批准；实际能力仍由本机 Agent 提供。运行中若只能下一轮应用，会显示预设状态；已经弹出的工具批准仍须在卡片中单独处理，切换不会自动批准它。保存失败不显示为成功，也不会悄悄按错误权限发送消息。群聊沿用对应角色会话权限，可进入该职能对话调整。

1. **组建团队**：选择工作电脑、游戏工程和工作目录，也可直接修改「工程路径」或选择「指定新的工程路径」。桌面版在选择本机时提供「浏览本机」文件夹选择器；手机 / 浏览器直接输入该工作电脑上的绝对路径。修改路径会自动匹配已有工程及对应工作目录；未匹配时显示自定义工程，不保留旧目录。保存时登记工程，无须手改配置；文件夹不存在时可勾选创建。为各职能分别选择 Claude、Codex 或已经配置并启用工具的 API Agent，以及模型和思考强度。每个任务创建独立会话。
2. **配置职能**：提供制作统筹、玩法、关卡 / LD、数值、系统、原画、模型 / 材质、场景 / LA、技术美术、UI / UX、音频、程序 / 集成、QA。制作统筹和 QA 必须启用，其余按需启用；统筹按本次需求选择必要职能。
3. **填写工具说明**：在职能卡片内展开「职责、工具与本机命令」，填写已有引擎 / DCC 路径、后台命令、构建脚本、资源规范、MCP 或其他工具使用说明。它们随任务发送给 Agent。此设置不安装工具，也不授予新的工具能力；Agent 使用本机已有能力和所选执行权限，缺少工具时必须报告。
4. **提出制作需求**：写明目标体验、范围、资源、约束和可核验标准。支持粘贴图片、拖入或选择图片、视频和普通文件，每次最多 5 个、合计 16 MB。桌面版还支持从资源管理器复制普通文件后粘贴（升级后重新打开桌面窗口生效）。先创建该需求专属 Git 分支和工作副本，再由统筹只读规划。
5. **选择流程与审批**：新建需求时选择「完整场景制作」「只做几个关卡」「只做设计讨论」「程序实现 / 修复」或自定义模板，再勾选本次需要的制作环节。拆解计划、玩法 / 关卡设计、原画视觉、实机场景 / 关卡和最终交付审批分别设置；不勾选的审批不等待制作人，勾选的节点必须由制作人确认，不能由 Agent 代批。设计或场景审批可按意见打回，上游制作与相关下游重新执行，旧记录保留。头脑风暴方案发起任务时也使用这份配置。
6. **执行与查看**：需求详情中的「职能对话」按角色展示聊天，每个角色可以选择其制作任务或独立讨论会话，支持文字、图片、视频和文件。执行中发送消息会排队；支持的 Agent 可点消息旁「立即引导」。工具批准和 Agent 提问可直接处理，也保留完整会话入口。手机以角色列表显示最近消息与进度，点击进入会话。
7. **QA 与交付**：勾选 QA 时，它在所选制作与审批之后执行；报告阻塞或缺少验证记录时停止推进。未勾选 QA 不会自动追加，也不会标记 QA 通过。统筹汇总交付后，勾选最终交付审批则等待制作人验收；关闭时显示「已交付」。已存在的旧需求保留原流程与审批配置。

## 基于已交付成果继续制作

在已交付需求详情顶部点击 **基于本次交付继续制作**，填写下一步目标，重新选择制作环节与审批，再交给统筹。默认建议为“场景搭建 → 整合实测 → QA”，等待计划、实机场景与最终交付确认，并录制成果展示视频；这些选项都可调整。它适合“原画和资产已经完成，现在把选定方案接入游戏”或在上一批关卡基础上继续扩展。普通新需求仍从团队配置的工程开始。

后续需求从上游实际工作副本创建独立分支，继承已跟踪改动及未被 Git 忽略的普通未跟踪文件，包括尚未提交的模型、材质和设计文档。沿用现有子模块隔离规则；忽略的缓存、构建产物不会自动复制，未跟踪 `captures/` 是否复制沿用团队设置。需要这些文件时，Agent 必须只读核对上游并复制必要资源到新副本，不能假设它们已存在。服务器保存上游需求、分支和路径、交付摘要、文件索引及审批来源；Agent 先核对文件，只执行这次所选环节。旧审批是来源参考，不能代替本轮审批或新场景验收。

上游需已交付、工作副本可用、执行和排队消息结束，并仍属于同一项目组和工作电脑；跨电脑迁移工程后不能直接继承旧路径。复制期间暂不接受会修改上游的职能对话或补录，完成后恢复。创建请求持有固定 ID，响应不明确时再次提交相同内容不会重复开任务；准备结果不明或源副本绑定变化会停止分发，不能回退到团队默认工程。上下游需求详情互相提供查看入口，原任务、完成记录和审批保留，不自动合并回源工程或主干。

例：上游只交付了 C 版场景资产，后续目标可写“复用 C 版资产搭建可玩房间，接入游戏入口，提供 Windows 本机启动命令及新场景运行视频”。应验证实际入口加载新房间；已有资产转台或旧默认场景运行成功，不能当作本次接入完成。

## 本次需求的流程配置

「只做几个关卡」默认沿用项目现有玩法和适用资产，执行玩法 / LD 设计、程序实现、关卡搭建、整合实测与 QA；不强制原画、资产规格、模型生产或数值设计。制作人可继续删选环节，按需要加入关卡设计审批或实机效果审批。关卡必须在需求副本中实际制作并验证入口，不以原来的默认场景冒充新关卡。

统筹计划中出现未选阶段或职能与阶段不匹配时，不分发这份计划；在上一轮已确认完成、会话空闲且投递收据明确时，退回原统筹会话修正，最多自动修正两次，仍不合规则显示阻断。原计划、会话与分支保留；不增加未选环节，也不自动批准视觉方向。

配置随需求保存，服务端根据所选阶段创建依赖和人工审批节点；未选阶段不会由统筹或调度器补齐。如果实际工作需要未选环节，Agent 应报告范围缺口。重启或断线不会丢失已完成阶段和审批，也不会自动替人确认。

## 旧需求的场景生产流程

以下兼容规则适用于未携带本次需求流程配置的旧需求；新建需求以表单中勾选的环节与审批为准。

提出需求时可选择「自动识别」「新场景 / 新资产」「场景复用」或「通用任务」。自动识别会根据场景 / 关卡需求启用场景流程；若统筹后来安排了原画、模型或场景美术任务，也会启用场景约束。明确选择通用任务后，不接受场景或正式美术资产生产计划。

新场景流程由服务端补齐并校验：**玩法与 LD 设计 → 场景原画 → 制作人视觉确认 → 数值配置、资产规格与生产、程序实现 → LA 正式搭建 → 集成验证 → 独立 QA**。任务列表按依赖排序。玩法与 LD 只做设计文档、布局和验收规则；程序在原画确认后统一实现一次，集成阶段复用这份实现，不另做玩法原型。数值与程序任务都由服务端视觉确认门禁拦截。默认依次执行，配置并行后才会同时执行独立任务。

- 原画职能必须交付工作副本内实际存在的 PNG / JPEG / GIF / WebP 图片；文字说明不能替代原画。每轮最多确认 12 张图片，单张不超过 16 MB。已有绘图 / 生成工具缺失时报告阻塞，不会直接跳到资产生产。
- 原画完成后，界面显示图片预览和「确认本轮原画，开放后续制作」「需要修改原画」。全部图片成功加载后才能确认。视觉确认由制作人操作，不能交给 Agent 代签。
- 原画预览按需求、任务轮次和审批版本缓存到服务器，重复打开直接复用，不反复上传完整原图；首次同步并发受限。点击「重新加载原画」会重新核对工作电脑上的文件。审批前仍实时读取本机文件摘要，文件变化会拒绝旧图确认；缓存不代替制作人审批。
- 确认绑定本轮图片版本，保存内容摘要和已确认预览。文件在预览后发生变化会拒绝确认；在后续制作启动前再次核对，变化则阻塞，不启动该任务。已确认图片可通过服务器缓存查看。
- 原画返工、驳回或对原画任务继续补充，会清除旧视觉确认，按修改意见重新出原画并等待新一轮制作人确认，数值、程序、资产、场景和 QA 的旧确认失效；已完成的玩法与 LD 设计保留。旧会话和交付记录保留。
- 复用流程必须由制作人填写既有视觉方案、资产位置与复用范围，仍需核对实际图片并确认，再编清单与搭建；不安排新资产生产。需要新资产时选择新场景流程，Agent 不能自行声明复用以跳过生产阶段。
- 场景流程需要启用原画、场景美术、程序，以及玩法 / 关卡 / 系统策划中的至少一项；新资产流程还需要模型职能。各职能继续使用团队中指定的 Agent 和模型。

升级时，尚未开始执行的旧场景计划自动补齐原画、视觉确认和资产环节，保留原任务、独立分支、计划确认与暂停状态。已使用旧场景顺序的需求先暂停后续分发，使用“应用新版流程，保留已有成果”更新：提前运行的程序任务经工作电脑确认停止后暂存，已产生的代码、文件和会话保留。原画获批后通过同一会话续做；已完成的数值在原会话复核，不从零重做。停止结果未确认时保留暂停状态，不自动重发停止。

## 暂停、返工与恢复

- 「暂停分发」暂停后续任务，当前任务继续。要停止当前任务，打开对应执行记录使用停止按钮；「取消需求」会向本需求的运行会话发送停止，并记录未确认的停止。
- 对已完成或阻塞的任务「返工 / 重试」，填写处理意见。该任务和依赖它的下游任务会重新执行，保留旧会话和旧交付回复。运行中的任务结束或停止后才能返工。
- 对最终交付汇总返工只重写报告；游戏本身有问题时，应对对应制作任务返工，从而重新执行下游及 QA。
- 电脑离线时保留需求和结果，待电脑上线后继续分发。关闭浏览器不会停止工作；服务端和本机连接程序仍需运行。
- 启动响应超时或服务重启时，结果不明确的任务会阻塞，**不会自动重发**。核对执行记录后，可绑定本次启动后、同电脑同工程且尚未绑定的会话，或在确认未执行后手动重试。
- 活跃需求期间锁定团队配置，避免执行中途更换 Agent。完成 / 取消需求后可修改。同一源工程可有多个需求，各自使用独立分支和工作副本。

## 执行与数据边界

每个新需求自动创建 `codex/studio-<需求 UUID>` 分支和 Git worktree，位于工作电脑连接程序数据目录的 `studio-workspaces/<需求 UUID>`，需求内所有职能在该副本工作。源工程必须为已有提交的 Git 仓库；无法隔离时阻塞，不回退到原目录。源工程的暂存 / 未暂存改动和普通未跟踪文件会复制到副本，源目录、源分支和暂存区保持原状；副本不保留源暂存分层。已初始化的子模块也建立隔离副本并复制现有改动；未初始化或无法复制时阻塞并保留现场。忽略的缓存、构建产物和导出文件不自动复制。未跟踪的 `captures/` 测试截图和录屏默认不复制（数量显示在需求详情），可在团队配置中勾选复制；原文件均保留。复制使用异步文件操作，避免阻塞聊天和连接保活。系统不自动提交、推送、合并或删除需求分支及工作副本。

默认每个需求同时执行 1 个任务，可改为 2–4。需求内并行依赖统筹按文件划分责任，没有文件锁。职能之间通过上游交付摘要、文件路径、验证记录、需求附件和工作副本传递成果，不会自动把所有会话全文复制给下游。单次上游上下文最多约 11,000 字符，完整交付记录可在界面查看。

引擎和 DCC 由 Agent 在工作电脑后台调用。网页提供团队管理，不提供桌面远程控制。尚未针对特定工程建立 Godot、UE、Blender 等专用执行器；填写已有命令并由 Agent 验证环境。

交付路径及验证记录来自 Agent 的报告；图片来自原有的会话图片通道。最终 QA 是独立 Agent 会话，不等于人工游戏体验验收。制作人仍需查看实际成果。网页显示工程内文件位置，不将整个工程自动打包下载。

角色独立讨论默认只读，不作为制作完成报告。对已完成制作任务继续补充，会重新开启该任务并使依赖它的任务与最终 QA 重新执行；其他任务仍在运行时需等待或引导当前任务。最近的制作人补充和附件会进入后续职能上下文；单次附件仍受 5 个 / 16 MB 限制，优先最近补充。若会话启动结果未确认，需核对完整会话后绑定，或人工确认未启动再解除等待，不自动重发。

升级前仅完成只读统筹、尚未开始制作的计划会保留，原统筹会话归入历史，后续制作改用新工作副本；已在源工程执行的旧需求会暂停并提示重新建立隔离需求。

团队和需求持久化在现有 Relay SQLite 数据库的 `studio_projects`、`studio_runs` 表中，保留执行会话 ID、投递动作 ID、状态、回复、交付物和制作记录。模型凭据仍留在电脑。沿用 Cookie 登录、同源写操作检查和已有 Bridge 鉴权，未增加新端口。

## 开发验证

`npm test` 包含编排、依赖、QA 阻塞、返工、暂停、重启恢复及已鉴权 HTTP / Bridge 路由测试。`npm run check` 和 `npm run build` 验证类型和构建。

`npm run smoke:studio` 是显式真实模型联调，会调用已有 Claude / Codex 登录、消耗四轮模型额度，并在 `.data/studio-live-<时间>/` 的隔离工作目录中创建四个新会话，验证拆解、跨 Agent 分发、QA、汇总和验收。测试不调用工具、不读写游戏文件，不代表任何游戏或引擎验收。结果保存为该目录中的 `proof.json`；失败记录为 `failure.json`。


## 团队群聊与生产过程 Review

会话工作台与游戏工作室在主页侧栏并列，使用同一套明暗主题、字体和中性色界面。移动端通过公共侧边栏切换工作空间。角色头像使用已保存的团队 UUID 和职能作为随机种子在本地生成，跨设备、刷新和切换任务保持一致，不请求外部头像服务。

需求详情中的“团队群聊 · 查看协作”与各职能对话并列。群里显示带任务 ID 的真实生产回复、任务分发、上游到下游的交接、阻塞、返工、工具审批和问题提示。新交接会持久保存当时的上游摘要和交付文件快照；计划重拆后仍可核对。系统协作记录与角色回复分别标注，不代替角色编造发言。工具输出的完整展开、公开执行步骤、图片/视频和历史尝试在职能对话内查看。

群消息可通过下拉框选择回应角色，也可使用 `@关卡策划 @原画`、`@level @concept` 指定多个已启用的角色。存在正在执行的职能任务时，消息进入当前会话；否则进入只读讨论会话。各接收角色得到共享群聊上下文，回答回到群里。选择“发到群里 · 仅记录”时不会调用模型，补充会进入后续制作任务上下文。私下新建、未加入群的角色讨论不会被汇入群聊。群消息及附件按需求隔离，重复消息 ID 不会重投；未确认投递会明确显示，刷新或重启不自动重发。

群聊不会跳过任务依赖、工具权限或本需求勾选的审批与 QA。群里提示需要制作人确认时，点“查看该职能完整过程”处理审批和问题。职能聊天按时间展示消息、工具调用、公开步骤、任务进度、交付文件和实际验证记录；标明角色、任务 ID、任务名称和时间。旧尝试只读，不混入本轮交付。实时刷新保留已展开的工具、媒体节点和阅读位置。


## 按项目组的头脑风暴

在“制作看板 / 团队成员 / 头脑风暴”中切换。每个讨论绑定所属项目组，默认由本机 Claude 讨论，带入团队配置、最近需求与任务进度；`project_context` 只能读取该组的源工程，讨论目录与游戏工程分开。讨论资料和模型登录仍留在工作电脑。

新建讨论可展开“模型与思考强度”，从本机 Claude 返回的模型中选择。讨论中点击当前模型即可修改，按讨论分别保存；运行中切换会预设到下一轮，沿用原会话和历史，不打断正在生成的回复。Codex 仍负责参考图生成。

Claude 可调用 `generate_image`，委托独立本机 Codex 原生 `image_generation` 生成实际参考图。成功图片返回到原讨论并保存在讨论资料目录；未产生实际图片时明确报错，不以代码绘图或占位图代替。停止 Claude 也会停止本轮出图。

认可方向后点“整理制作提案”，Claude 通过 `propose_task` 生成提案卡，制作人点击“发起制作任务”才创建制作需求。提案与参考图、最近讨论背景随需求传递；完整讨论快照和提案编号保存在 `brainstorm_launches`。同一提案重复点击返回同一需求。发起前可选择本次制作环节与审批；制作沿用独立 Git 分支 / 工作副本，讨论参考图不会代替本次勾选的制作阶段视觉批准。

手机和 PC 支持 Markdown 表格、SVG 与 Mermaid 流程图等预览，提供放大、横向查看、下载 SVG 和源码。SVG 清理后作为独立图片渲染，不执行脚本、不加载外部资源。附件里的 `.svg` 也支持预览。

为了不打断已经运行的任务，可启动同一工作电脑的独立头脑风暴进程：`.data/brainstorm-bridge.config.json` 使用原工作电脑 ID，设置 `service: "brainstorm"`、独立 `dataDir`、`syncHistory: false`、`projectSourceDataDir` 指向原连接程序数据目录；保留允许的源工程。运行 `scripts/start-brainstorm.ps1`。新版本会话工作台与桌面启动器在存在此配置时启动它，生产会话仍由原连接进程处理。原连接程序也支持头脑风暴；独立进程提供隔离与不中断升级。
## 成果展示视频与交付预览

提出需求时可勾选“完成后录制成果展示视频”，默认勾选，也可在头脑风暴提案转任务时选择。系统在制作后、QA 或最终场景确认前安排展示任务；原画方案只可明确标注静态方案轮播，资产用真实 Blender 模型巡览，已实现关卡录制实际运行，不能混淆展示范围。

已完成需求可点“补录成果展示视频”。它保留原分支、工作副本、已完成任务与批准记录，只追加录制和更新交付汇总；旧交付记录保留供核对。缺少录制工具或验证失败仍按阻断处理。

视频保存在本需求工作副本 `.studio/<需求ID>/studio-showcase/`，网页内联播放。服务器通过分段 Range 流中转，不写入视频缓存；历史消息中引用该目录视频也不会自动上传进普通媒体缓存。电脑离线时视频不可播放。交付图集按任务实际声明文件去重，图片完整显示并提供加载失败重试，不使用历史消息中的旧图片列表。

## 断点续做与独立后台

每次任务投递、状态变化、交付和制作人审批均写入本地数据库。工作电脑重连后，中断的绑定会话会成为执行断点；需求详情和任务详情可点“从断点继续”，继续原会话和原工作副本，保留已完成前置任务与审批。规划、职能制作和最终汇总均支持恢复。未知投递不自动重发；QA 阻塞、原画返工继续走原有处理流程，不能用恢复代替审批。

Windows 启动入口安装当前用户的 Task Scheduler 后台任务，分别看护主连接和头脑风暴连接。后台独立于 Codex 和 Electron 窗口，登录后自动运行，进程退出后重启。日志及安装信息位于 `.data/background-service.log` 和 `.data/background-service.json`；任务以 `AgentRelay-` 开头。首次接管会等待已有连接，避免重复执行 Agent。


## 本机与真机验收

可直接在职能对话说“启动这个场景”或“在 Windows 本机打开试玩”，在群聊选择回应角色也可。Agent 先核对本需求 worktree、真实场景与指定引擎，再通过本机工具运行已有入口；Windows 游戏窗口应可见。问“对应 worktree 在哪、怎么启动”时，直接回复绝对路径、实际项目目录、场景/启动脚本/EXE 及可复制的 PowerShell 命令。启动后还须返回 PID、日志路径和真实就绪或失败证据，不能仅凭进程存在宣称加载成功。

普通咨询不自动拉起程序；明确启动不算源文件制作变更，必要缓存和日志留在工作副本。已有相同场景进程时避免重复启动，启动结果未知先核对，不自动重试。只有原画/模型或没有运行入口时，如实说明并给出资产预览方法，不拿旧场景代替、不编造命令，也不因一句“启动”自动补做场景或改源码。

“已交付”表示本次所选流程完成，是否可玩取决于交付范围。只选原画和资产生产时，先看图片和展示视频，再用指定 Blender 打开源文件或用指定定制引擎查看 GLB；没有组装、集成的房间不会自动出现在旧游戏入口中。

需要试玩时，新需求明确复用哪次交付及其工作副本中的资产，按需选择“关卡 / 场景搭建”“整合与实测”“QA 验证”，并启用实机场景和最终交付审批。交付必须写清工作副本、分支、引擎版本、真实游戏入口、实际加载的新场景、启动命令与操作步骤。Windows 在工作电脑启动该入口或打包 EXE；Android 安装目标平台 APK，iPhone 需要目标平台构建与签名后安装。仅远程查看网页或演示视频不等于真实设备试玩。

验收应在指定设备实际运行：检查加载的新场景、移动和交互、通关条件、画面及性能，保存设备型号、构建标识、日志、截图和录屏，再由制作人确认。此流程不会自动提交、合并或发布源码。

## 共享工具环境与技术阻断复核

团队配置中的“工具环境”可单独保存，不必取消制作需求或重配职能。Blender、Python、引擎、Python 依赖目录和工具搜索目录属于所选工作电脑；相对路径以该需求工作副本为准。源工程的配置与工具缓存可只读核对，便携工具可以直接使用绝对路径，输出仍必须写入工作副本，不为工具缓存复制整个 captures。

`scripts/discover-studio-tools.mjs` 只读检查明确路径、项目/源工程缓存、PATH 和常见安装目录，实际执行版本探测并以相同 Python/PYTHONPATH 导入依赖，不安装软件、不修改构建记录。示例：`node scripts/discover-studio-tools.mjs --project <工作副本> --source <源工程> --blender <blender.exe> --python <python.exe> --python-path <依赖目录>`。未加 `--needs` 时只是清点工具；必需项通过 `--needs blender,python,xatlas` 显式指定。显式固定的路径失效时不能偷偷切换另一版本。报告中工具可用不等于资产、构建来源、运行画面或发布验收通过。

制作提示按实际新制、修复、复用操作确定工具要求。纯复用不为了流程名称重建资产，但历史未验的冷加载、UV2/receiver 和质量门禁仍须补验。程序已完成后的合法文件更新与未经授权资产变化分开核对，最新实现交付优先补入上下文。

`STUDIO_RESULT` 可附 `blockers: [{category, code, details, remedy}]`，类别包括 environment、provenance、upstream、quality、other。仍有硬阻断不能声明 done。任务详情显示证据与恢复步骤；“复核阻断并继续原任务”使用原会话、原分支和文件，仅重验本任务，不重跑已完成的前置阶段或批准视觉方向。需要前置/审批完成、原会话空闲、最后投递结果明确；未知投递和正在执行的任务不会自动重发。
