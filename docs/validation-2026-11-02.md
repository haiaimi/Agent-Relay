- Claude 旁问、命令补全和任务执行期间排队；协议测试覆盖 Claude 原生/托管及 Codex 托管/桌面的逐条引导、拒绝回队和投递未知时不重发。
- 真实桌面 owner 发现与能力显示已验证；没有向用户正在执行的真实任务注入引导测试。桌面真实模型接收仍需使用中验收。

- HTTPS 证书、relay/nginx 运行及发布资源一致性检查通过；证书续期定时器已配置。

## 排队与旧失败刷新修复

- 新增空闲原生 Codex 通过既有桌面 owner 发起下一轮；窗口保持打开不再阻止队列出队，不启动第二个 transcript writer，继承原窗口权限设置。
- 原生状态覆盖已失效的中转状态；历史重放不改写当前状态，无关元数据进程退出也不再把原生任务标为失败。
- 原生数据库消息携带创建时间，网页按时间合并本机记录与中转事件，旧错误不会固定在最新回复后面。历史响应附带当前会话状态，手机回到前台时立即刷新。
- 33 项自动测试通过，包含空闲 owner 续聊协议、逐条出队、未知投递不重试、历史状态隔离及时间排序；线上实际页面确认旧错误之后显示后续提问和新回复。未向用户正在执行的任务注入测试消息。

- 移除网页自有的相机/照片/文件菜单；会话与新建会话的添加按钮同步触发一个不限制类型的原生 file input，由系统提供选择来源，继续支持多选、预览、移除、粘贴和拖入。
- 前端语法与线上资源一致性检查通过；线上浏览器验证两个入口均单击触发 filechooser、选中文件后显示预览，验证草稿已移除，未发送或上传。iOS 原生菜单的具体展示仍需真机确认。

## 原生空闲续聊协议版本

- 修正所有 IPC 方法统一发送 v1 的错误：桌面发现和引导是 v1，空闲续聊是 v2；错误版本会在路由的能力发现阶段被拒绝，表现为 no-client-found。
- 协议测试新增原生路由的版本校验行为。在本机真实桌面用内外 thread ID 故意不匹配的无消息探针验证：修复前路由拒绝，修复后抵达续聊处理器并由 thread ID 校验拒绝，未触发模型任务。失败的两次发送未出现在原生消息索引中，未自动重发。

## Agent 图片输出

- 补齐 Codex 原生 imageGeneration / imageView、兼容日志记录和本地 Markdown 图片链接；生成结果可从历史内嵌图像恢复，不依赖保存路径一直存在。MCP/工具结果中的图片独立显示，工具文字保持折叠。
- 34 项测试通过，涵盖生成图片/图片查看的规范化、缺失保存路径时恢复图像、原生历史到鉴权下载、会话隔离和离线缓存。历史旧页在电脑在线时打开或加载可补同步，尚未重读的旧缓存不视作已同步图片。

## 成功回执误报

- 原生桌面 IPC 转发层会移除内部 method 包装；续聊和引导的结果应从 reply.result.result 读取。此前多取一层导致原生端已收到消息，但网页误报结果未确认。已修正两条路径及测试响应格式。
- 使用原生消息 client ID 审核用户反馈的三次续聊，每条各一条，没有自动重复投递。真实桌面的只读设置查询确认成功响应不含多余的内部包装；协议测试覆盖准确的续聊/引导回执以及队列只消费一次。
