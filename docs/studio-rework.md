# 制作阻断与自动补做

自动补做保留实际失败和已选审批，不会把等待恢复条件当作验收通过。

## 工具要求

默认通过受支持脚本实际运行和验证。规划自行加入的 Computer Use、Finder/App 绑定或真实键盘门禁会被退回统筹修正；制作人明确要求的人工试玩继续保留。旧会话收到这些工具阻断时，系统只自动纠正一次操作路线，业务断言与画面证据要求不变，仍失败则等待具体恢复条件。

## 有限重试

同一组恢复条件下，同一阻断最多自动原地补做两次。第三次仍失败时，可由程序解决的内部问题转阶段内程序协作；不适合转交的问题进入“等待恢复条件”。协作任务也受预算约束，不递归创建修复任务。

即使错误代码不断变化，单个任务自动补做最多五次，或从首次失败记录起经过三十分钟后停止继续派发。等待时间继续逐步延长，识别到重复失败不会缩短成三秒。预算不强行中止已经开始的任务，而是在下一次分发前判断。

报告改写、轮次变化及自动补做提示不能刷新预算。新的制作人阶段指引、明确手动复核、工具配置更新或实际完成的上游新交付可以建立新一轮恢复条件。程序协作完成后，原职能获得一次复验机会；同一修复再次失败不会再次循环转交。

## 外部条件与文件责任

`STUDIO_RESULT.blockers` 可提供 `requiresExternalStateChange: true`、`retryableWithoutExternalChange: false` 和 `ownerTaskId`。恢复标志会保留；旧记录中原始结构化结果里的标志也参与判断。需要外部条件变化的任务停止原地重试，恢复条件写在 `remedy` 中。制作人可以在条件恢复后补充阶段指引，或在页面核对变化后继续。

内部程序缺陷不要求下游验收先完成。系统创建当前阶段内的程序修复任务，继承原任务的前置步骤和审批，原职能等待它完成再复验。修复任务不能依赖自己或原验收任务；检测到循环或缺失依赖时停止分发并保留原审批。

## 页面状态

“等待恢复条件”表示自动派发已经停止，并非 Agent 正在工作，也不是新增的制作人审批。页面保留失败原因和继续入口；显式审批、未回答的问题、未知投递回执、暂停和工作电脑离线仍按原有规则处理。
