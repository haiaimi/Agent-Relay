# 当前阶段指引与渲染验收适用性

任务详情中的“当前阶段指引”允许制作人补充方向：

- 未启动阶段只保存指引，前置依赖和审批完成后带入任务；不会提前执行。
- 已阻断阶段使用原会话继续，保留 worktree、前置成果、原失败记录；受影响的后续任务重新验证。
- 执行中先沿用原会话投递，确认排队回执后对同一条消息调用已有 steer 通道，避免第二个 writer。即时引导未确认时明确显示排队/核对提示，不盲目重复发送。
- 阶段中待回答问题和工具审批仍在本页处理；指引不代替批准。已结束需求、人工审批节点不开放这一生产入口。
- PC Enter 发送，Shift+Enter 换行；输入法确认不误发，手机 Enter 保持换行。刷新进度保留本页草稿；保存记录显示任务归属和投递状态。

`POST /api/studio/guidance` 使用消息 UUID、runId、taskId、expectedSessionId 和 text。服务器校验任务/会话/工作副本归属，保存指引后才投递。相同 UUID 的重复请求不重复发送；不同正文复用 ID 会拒绝。未知投递保留 `uncertain` 及回执，须核对原会话；不会因超时重复启动或重发制作任务。

## 渲染门禁

Relay 不硬编码某个游戏永远使用 Voxel，也不按“UV2”关键字自动跳过任务。规划、新任务、原会话补充均先要求核对工作副本启动器、预设、覆盖参数、引擎及日志。`discover-studio-tools.mjs` 的 `rendering` 提供本副本配置路径与 SHA-256，明确 `runtimeVerified:false`，不读取源工程配置替代当前副本的配置。

识别到实际无 receiver 的 Voxel 后，旧 Lightmap/UV2/receiver 覆盖要求记“不适用”，保留撤销原因；真实冷加载、依赖、画质、玩法与同条件 CPU/GPU 失败仍阻断。显式 Lightmap 路径依然检查实际 receiver 覆盖；未知或冲突配置先调查，不能自动免验。游戏侧对应文档为 `project/docs/SCENE_GI_ACCEPTANCE.md`。

## C 房间案例

旧任务标题和历史标准残留 UV2；当轮报告已撤销该项，剩余 `C_GI_VISUAL_NOT_ACCEPTED` 和 `C_PHYSICS_CPU_REGRESSION`。旧 240 帧报告 C 物理处理均值 380.675ms，对照 3.466ms，不能因为 Voxel 不用 UV2 就宣布通过。

“当前任务等待下游先修复、下游又依赖当前任务”会死锁。应明确文件责任和最小修复方案，制作人在当前阶段协调；不通过跳过或假完成来隐藏真实失败。Relay 提示已明确禁止这种修复安排。

## 验证边界

自动回归覆盖：未分发阶段不越依赖、同会话续做、上游保留、原 writer 引导、重复 ID、未知回执不重发、待审批保护、无 receiver / 未知 / 损坏配置。网页及服务验证不代表 C 房间的光照或性能问题已经修好。
