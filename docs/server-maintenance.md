# Relay 服务器缓存与部署清理

## 2026-11-05 实际维护

磁盘占用从 97% 降至 44%，释放 19.65 GiB，空闲约 20.88 GiB（df 显示 21 GB）。主要原因是累积的历史部署目录，多份重复包含约 750 MB 的 node_modules。

- 删除 100 个未使用的历史部署目录、127 个超过一小时的临时部署文件。
- 清理 npm 内容缓存、pip 下载缓存、apt 包缓存和可重建缩略图。
- 保留当前发布、最近已验证回滚版本及保留版本/进程/安装链接实际引用的依赖；共保留 3 个部署目录。
- 保留会话数据库、1100 个会话、4 个制作需求、1 个团队、4401 条媒体引用、图片原件、上传文件、工作流记录及数据库备份。无无引用图片可删。
- 清理过程中 Relay 保持运行；清理后健康检查成功，3 台设备在线。数据库 `PRAGMA quick_check(1)` 返回 `ok`。

维护清单保存在服务器 `/var/lib/agent-relay/maintenance/cache-cleanup-20261105.json`，记录实际删除路径、保留路径、空间变化和数据计数。

## 后续维护约定

部署前检查目标分区可用空间，除新版本所需空间外留出至少 2 GiB 余量；不足时先清理，不先停止服务或切换 current。避免每次发布无期限复制完整 node_modules；保留当前与最近可用回滚，并检查进程及符号链接依赖后再清理旧版本。

清理必须以明确绝对目录为边界，不能跟随符号链接删除用户数据。`images` 包含会话原件和原画审批引用，并非全是可随意删除的缓存；只有确认没有媒体/审批引用的孤儿文件才能删除。`previews` 为派生缩略图，可重建。上传文件和历史数据库不按缓存处理，不通过清空数据库、删除 WAL/SHM 或强行 VACUUM 来腾空间。

连接故障按一分钟间隔最多尝试五次；未知写入回执先核对原记录，不重复执行生产任务。磁盘耗尽导致 SQLite I/O 错误时先恢复空间，再检查服务、真实请求与数据库完整性。

本轮再释放 2.58 GiB，磁盘占用降至 38%，空闲约 23.33 GiB（df 显示 24 GB）。运行数据库 freelist 只有 1 页，不做停机 VACUUM。实际清单：`/var/lib/agent-relay/maintenance/second-cache-cleanup-20261105.json`。
