# 架构与数据约定

## 执行路径

浏览器与 Electron 桌面共享网页工作台。会话工作台和游戏工作室共用常驻侧边栏，工作室通过同源内容面板保留状态；移动端主内容固定在视口，抽屉单独移动。跨面板导航通过受来源校验的消息交换完成。

`src/relay/server.ts` 提供 HTTPS 入口后的 HTTP/WebSocket 服务、登录及会话隔离。`src/bridge/connector.ts` 在工作电脑主动连接服务器，`src/bridge/runtime.ts` 调用本机 Codex app-server、Claude SDK 或配置的其他 Agent。模型凭据和工程工具留在工作电脑，不从服务器直接操作项目。

## 工作室

`src/relay/studio.ts` 持久保存项目组、需求、任务、独立工作副本、分支、会话绑定、执行尝试及审批记录。`studio-flow.ts` 定义可选阶段，`studio-scene.ts` 处理场景依赖，`studio-channels.ts` 和 `studio-group.ts` 提供职能与群聊记录，`brainstorm.ts` 管理项目组内的讨论与转需求。

需求先准备独立 Git 工作副本，再由统筹拆解。只调度勾选的阶段，并验证职能与阶段匹配。任务按依赖推进；人类审批是显式门禁。原画修改后下游确认失效，反馈回到原任务。跳过任务保留跳过原因，不把未执行的检查写成通过。

恢复使用原需求、分支、工作副本和会话。完成任务不会因重启重新执行；未确认投递保留待核对状态，不能自动重复发送。格式或阶段不合规的明确完成结果可有限次在原会话纠正，区别于投递结果不明的重试。

## 会话与模型

本机历史与 Relay 管理的运行状态合并展示。原生 Codex 桌面通过本地 IPC 所有者通道操作：Windows 命名管道、macOS/Linux 当前用户的 Unix socket。发现所有者后让原所有者续聊，不创建竞争的 transcript writer。没有可用所有者时尝试独立续聊；写入锁冲突保留原排队消息并等待，避免状态在失败尝试中反复跳变。

网页选择模型可保存为下一轮偏好；不要求立即接管原生会话，也不改变已在执行的一轮。偏好持久保存并在实际投递确认后消费。投递不确定时不自动重试，保留核对入口。

## 文件与媒体

用户附件与任务交付物是两条独立来源。消息只呈现用户文字及去重附件；内部路径提示不作为额外用户消息。交付页以任务声明的 `artifacts` 为准，保留来源任务，去重后显示图片或视频，不能用历史消息中的所有图片代替当前交付清单。

原画从本需求工作副本读取，路径受项目、会话及工作副本边界检查；预览按需求、任务、轮次和文件身份缓存。制作人批准前重新读取本机原件哈希，缓存不能代替审批时核验。

成果视频通过 `/api/studio/video` 从工作电脑分段流式中转。单段最多 256 KiB，服务器不写视频文件、不登记视频内容缓存，响应为 `private, no-store`。支持 HEAD、Range、206/416 与移动端内联播放。读取期间文件版本改变即停止，防止拼接不同版本。工作电脑离线时视频不能播放。普通附件/图片原有缓存策略独立于该成果视频接口。

## 持久化与升级

运行数据在配置的数据目录，真实配置、密钥、SQLite、工作副本和素材不进入 Git。升级前备份数据库及配置，保留旧发布目录；不要删除或迁移任务状态来解决页面问题。服务器重启后电脑重连；重启电脑端前先检查它管理的执行、审批、排队及未确认操作，防止中止实际任务。
