# 工作室确认与恢复

制作需求的待确认事项集中在“需要你确认”区域：看板显示当前项目组未结束的需求，需求详情、任务详情和职能会话显示当前需求。每项标明职能、任务 ID 和任务名称，不必跳转到各角色的完整会话寻找。

## 直接处理

- **Agent 提问**：显示原问题、选项和自填回答。提交回原会话；排队时明确提示。刷新不覆盖正在填写的回答。
- **工具批准**：显示执行器提供的操作说明与命令，可允许这一次或拒绝。结果不确定时等待核对，不自动批准第二次。
- **制作人审批**：显示所选流程中实际存在的计划、视觉方向、设计、实机场景或最终交付。视觉审批仍要求图片全部加载、内容校验及本轮版本匹配；没有勾选的审批不会因此新增。

问题回答、工具批准和制作人审批是不同操作。回答问题不代替视觉审批；跳过制作任务不代表 QA 通过。任何确认都需要制作人主动处理，系统不会代选。

手机的需求和任务详情使用单层内容滚动，标题和关闭入口常驻。职能会话中的确认区域独立滚动，保留消息与输入区域。

任务页默认只显示当前步骤的情况、原因、恢复建议与下一步，以及一个对应的主要操作：回答问题、确认操作、补齐原画、继续断点、检查环境或请 QA 重新实测。状态同步失败、电脑离线、前置审批未完成和其他工作仍在运行时，优先核对或处理前置条件，不建议重复启动。交付格式缺失与真实 QA 失败分别提示，已验证可用的 Blender/Python 不会仅因出现在报告里被判断为缺失。

图片、视频与本轮待确认成果直接展示。与当前步骤无关的问题和审批保留在需求总览及对应任务，不混进当前任务页；临时切换步骤和刷新问题卡保留正在填写的回答。聊天、返工、跳过、自修复、其他任务进度与完整执行记录统一收在“更多操作”。业务审批保留“认可并继续”和“提出修改”两个必要选择，原画版本与内容校验不变。

“查看待处理”会直接定位到目标任务的具体内容。已经处于该任务时，按钮显示“查看本任务阻断原因”或“查看本任务待确认事项”；重复点击仍会滚动到对应区域、显示聚焦框和定位提示，不会只重新打开同一个详情。阻断任务直接展示本轮原因、阻断代码和恢复建议，区别于返工要求与历史失败。定位只滚动详情的内容区域，不移动整个页面，不自动执行或审批任务。

## 操作含义

| 操作 | 行为 |
| --- | --- |
| 处理上方待确认事项 | 定位并刷新当前页的确认内容，不新开制作轮次 |
| 交给 Agent 继续处理 / 请 QA 重新实测 | 原“复核阻断并继续原任务”：在原会话检查失败项并补做，保留已完成的前置任务 |
| 继续上次工作 | 从保存的断点恢复原会话；有问题或批准未处理时，先显示待确认事项 |
| 重新返工 | 在“更多操作”中填写新意见，重做对应任务并重新验证受影响的下游 |
| 跳过本步骤 | 在“更多操作”中保留失败与跳过原因，满足安全停止条件后释放后续依赖；不伪造验收通过 |
| 完整执行记录 | 在“更多操作”中查看全部工具步骤和历史，用于深入排查 |

页面不再统一使用含义模糊的“继续处理”：QA 显示“请 QA 重新实测”，图片缺失显示“请 Agent 补齐原画”，中断显示“继续上次工作”。这些操作沿用现有受校验的恢复接口，不等于验收通过或重做所有前置任务。请求已确认或结果不确定时，主要按钮改为核对处理进度，避免重复投递。

## 状态读取与投递超时

工作室状态支持 ETag：状态未变化时返回 304，复用浏览器中的对象。前端合并刷新请求并限制高频事件触发；普通状态读取等待 30 秒，操作请求等待 95 秒，覆盖服务器最长 90 秒的转发窗口。

后台状态读取失败保留原有内容，在状态区域提示，一分钟后重试，最多五次；手动刷新可重新核对。执行器待确认发现失败也采用一分钟间隔、五次上限。离线与同步失败不代表审批通过或工作完成。

投递请求不做自动重发。问题回答和工具批准复用操作 ID，通过现有持久化操作记录防止重复执行。已收到成功回执但后续刷新失败时，显示“已送达，进度暂未同步”；没有成功回执时显示“操作结果暂未确认”，保留输入与附件供核对。不要仅因为状态暂未刷新就反复点击发送。

## 维护约定与验证

`GET /api/studio/attention?runId=...` 需要已有登录，仅汇总该需求当前工作副本的关联会话；排除旧任务轮次和其他设备、工作副本。返回问题和批准内容，不返回完整聊天历史。等待中的原生问题通过后台只读 history 发现，回答和批准仍走 `/api/actions`；生产审批仍走原工作室命令及版本校验。

自动化验证覆盖会话范围、已解决问题不复活、工具批准状态、原生发现合并、离线与失败退避、ETag、鉴权和不重发不确定写入。浏览器隔离测试验证任务页直接回答、工具批准、审批后数量和侧栏进度更新、刷新保留草稿，以及 390 × 844 手机布局。测试不批准正式任务，也不操作游戏工程。

## 回答已送达但仍显示“请回答问题”

旧设备连接程序可能在服务器通过原会话成功投递回答后，仍上报旧问题计数。Relay 现在用只读 live history 的具体问题身份与已确认回答记录纠正计数，并过滤已回答卡片；不按历史回答总数盲减，也不把后续有工具活动当作回答已送达。新问题事件、变化的计数、不同问题内容、不确定回答、旧快照和工具审批保守保留。纠正结果可跨服务器重启和旧执行器重连继续生效。

连接程序也增加了托管会话续做后的 async 问题核对，保留真正的原生问题。该部分在连接程序下次安全更新后生效；服务器兼容修复无需重启正在制作的本机 Agent。


## 执行问题自动回答

普通执行问题默认由团队自动决策。新需求的 `autoAnswerQuestions` 默认为 true；旧需求未保存此字段时也按启用处理。创建需求和需求详情都可关闭。制作人选中的计划、设计、原画、场景和最终验收审批仍由原审批节点处理；仅启用最终验收，不会使中间所有实现问题都必须人工回答。

任务提示优先要求当前职能按需求、已确认方案和最新制作人指引直接推进。若执行器仍产生问题卡，服务器后台主动发现，核对实时问题身份后延迟约 10 秒回答，无需手机或网页保持打开。有自填选项时，将最新指引交还当前职能做具体工程判断；固定选项优先匹配明确指引、需求与推荐项，排除“暂不决定”等阻断选项。只在当前需求工作副本和已选阶段内执行，Agent 自行制定的文件分工可协调，显式制作人限制仍有效。

回答沿用原任务、原会话及原 worktree，通过同一个操作日志与问题投递通道送达。异步问题保留原始工具调用 ID 和问题序号；排队时尝试原队列的即时引导，不创建第二个任务或原生写入者。“团队自动回答”与决策依据写入问题卡和任务制作记录，后续职能可读取，用户可随时补充指引纠正。

暂停、取消、已交付、审批节点、外部会话、前置依赖未完成及迁移未完成的需求不自动提交问题答案。密码等真实凭据不会生成；工具批准仍遵守会话权限。真实质量或运行错误不会自动标记为通过，缺少真实试玩者/测量等资料不能编造。

投递使用持久化身份去重，人工回答已在途时不抢答。服务重启可采用已确认回执，不重发结果未知的操作；实时状态读取和明确尚未投递的离线故障最多尝试五次，每次间隔一分钟。后台自动回答需要服务器版本包含该功能；托管 Codex 异步问题的主动发现需要连接程序相应支持，旧执行器仍可使用已有问题卡和服务器的无桌面兼容投递。
